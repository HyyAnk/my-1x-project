# Phase Report

## Result

Use PASS, NEEDS_WORK or BLOCKED. State the exact phase and inspected commit/worktree baseline.

## Reproduction

List each finding ID, fixture setup, expected versus observed behavior before repair, and deterministic failure injection point.

## Implementation

List modified files and explain responsibility boundaries, persisted contract changes and compatibility policy.

## Verification

For each command record date, exit code, tests/failures/skips and limitations. Include post-repair observable results, storage hashes and restart behavior where applicable. Do not substitute test totals for workflow evidence.

## Remaining work

List unresolved defects with severity, reproduction, owner phase and next action. Explicitly distinguish unsupported environment checks from product failures.

## Safety

Confirm isolated storage, no live migration, no translated Bank write-back, preservation of existing work, and no subagents.
