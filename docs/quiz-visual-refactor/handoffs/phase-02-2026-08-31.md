## Capability contract

- Authoritative types/catalog: `packages/shared/src/quizLayouts.types.ts` and `quizLayouts.catalog.ts`, exported through `quizLayouts.ts`; Sandbox context mapping and its response schema are isolated in `sandboxPreviewLayoutPolicy.ts`.
- Compatibility result and reason codes: `evaluateQuizLayoutCompatibility` and `resolveQuizLayout` in `quizLayouts.policy.ts`; discriminated results use `compatible` or `ok`, with seven stable codes from `QUIZ_LAYOUT_INCOMPATIBILITY_CODES`.
- Auto policy: `visual_choices_three` for `visual_multiple_choice` or `odd_one_out`; `media_left_choices_right` otherwise. Candidate compatibility is evaluated deterministically before selection.
- Explicit incompatibility policy: return `{ ok: false, requestedLayout, source: "explicit", issues }`; never select another layout.
- Canonical metrics owner: production entries in `QUIZ_LAYOUT_CATALOG`; preview-only `baseline` metrics live in `QUIZ_PREVIEW_BASELINE_CAPABILITY`; generic non-layout and choice asset defaults also live in shared policy.
- Persisted compatibility: `QuizLayoutIdSchema` is unchanged and still parses `auto`, `media_left_choices_right`, and `visual_choices_three`; `baseline` remains excluded from production IDs.

## Behavior and deviations

- Intentional behavior changes: explicit incompatible Director beats now produce blocker issues; incompatible Sandbox previews return structured HTTP 400. Valid auto and explicit requests retain IDs and render semantics.
- Persisted-data compatibility: no enum/schema ID migration and no stored Director-plan rewrite. Existing incompatible explicit artifacts remain readable but must be corrected before validation/render.
- Supported versus recommended: `visual_choices_three` supports visual `multiple_choice` while recommending `odd_one_out`; recommendations do not affect validity.
- Media enforcement is semantic capability validation, not a new requirement that generated files must exist. Existing fallback asset behavior remains intact.
- The brief's “shared unit tests” run through the server Vitest harness because `@studio/shared` has no test runner; the tests import and execute only the shared pure policy for those cases.
- No ADR changed: implementation follows ADR-001, ADR-005, and ADR-006 without introducing a new architectural decision.
