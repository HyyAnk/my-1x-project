## Shared architecture

- Scene model types: `quizScene.types.ts` explicitly models question/choices, stable order and labels, canonical answer state, accepted layout capability, presentation, resolved styles, palette, media source/fallback, aspect ratio, mascot occupancy/anchor, brand visibility, phase, and final-scene state.
- Pure state adapters: `productionSceneStateAdapter.ts` maps compiled event boundaries; `sandboxSceneStateAdapter.ts` maps explicit phase and exact 1.2/2.5/7.5/8.8-second scrub boundaries into `QuizSceneState`.
- Normalization: `buildQuizSceneRenderModel.ts` is the single deterministic model builder. `productionSceneAdapter.ts` and `sandboxSceneAdapter.ts` supply surface inputs without provider/filesystem I/O in the core.
- Shared part builder: `buildQuizSceneParts.ts` constructs question, counter, hero, choices, phase, fact, reward, brand, and mascot semantics; `renderQuizSceneParts.ts` renders the stable question/counter/hero/thinking/brand parts.
- Production adapter: `questionClip` passes the successful Phase 2 resolution into `adaptProductionQuizScene`; compiled events still control CSS timing and reward/fact visibility.
- Sandbox adapter: `buildSandboxComposition` parses capability-valid input, renders mascot at the boundary, calls `adaptSandboxQuizScene`, and retains explicit phase/scrub snapshot behavior.
