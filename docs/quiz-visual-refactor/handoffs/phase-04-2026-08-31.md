## Unified contracts

- Normalized choice model: `QuizSceneChoice` retains stable `id`, `order`, `text`, and resolved-or-fallback `media`; it no longer stores renderer-derived label or state.
- Choice-group renderer: `renderChoiceGroup` sorts by normalized order, creates A/B/C labels, calculates state from `correctChoiceId` and phase, emits stable group/card semantics, escapes untrusted text/attributes, calculates existing tiers, and replaces missing media with a deterministic illustration while retaining choice text and accessible labels.
- Skin contract: `AnswerCardSkin` exposes identity, a stable class, optional per-card class/decorative/status hooks, and CSS. No skin iterates choices or derives identity, correctness, labels, phase, tiers, escaping, or media behavior.
- Unified layout slots: `QuizLayoutSlots` contains `questionBoxHtml`, `heroHtml`, `choicesHtml`, and `phaseHtml`. Baseline, `media_left_choices_right`, and `visual_choices_three` all consume the same choice slot.

## Behavior and deviations

- Intended visual-skin parity changes: visual choices now receive the selected `glossy_arcade`, `comic_chunky`, `glass_neon`, or `minimal_soft` skin instead of the old generic visual card. Text and visual choices now share stable semantic markup, labels, phase states, escaping, tiers, and fallback behavior across production and Sandbox.
- Responsive correction: visual QA found the third portrait visual card ending at 2246px on a 1920px canvas. A focused layout-owned rule sets `.layout-visual_choices_three .option-image` to 360px only under `#stage[data-aspect-ratio="9:16"]`; the authoritative full-canvas rerun ends at or before 1855px in Sandbox and 1844px in production. This is capacity preservation for the migrated markup, not the broad Phase 5 CSS rewrite.
- Production timing compatibility: production passes `revealStart` into its static scene snapshot so compiled timeline CSS continues to control when the canonical reveal classes become visible.
- Schema/choice-count confirmation: shared and Sandbox schemas remain at two choices for true/false and three for other current formats. Four choices remain rejected before rendering.
- Deviations from brief/ADR: none. No skin reclaimed workflow logic; the Phase 3 model had sufficient canonical data; no external consumer required a compatibility path; no layout/style/background/preset or four-choice contract was added.
- Environment: system Node 26 has a broken Corepack pnpm shim, and direct web tests under Node 26 failed because JSDOM exposed no `localStorage`. The bundled Node 24 runtime was prepended for every accepted rerun and all final evidence.
