# Manual Flow Acceptance

Status: not performed. The user controls https://flow.google.com/ and all generation/extend/publication actions. This checklist does not authorize an agent to operate the site or incur generation charges.

## Two Required Samples

Use one approved bank question from each archetype: Versus Face-off and Deep Trivia. For each record source question ID, reel/package revision, reference hashes, intended segment durations, user-observed model label/date and an evidence reference the user is comfortable sharing. Do not place credentials or private account details in reports.

## Before Generation

- [ ] Package source question and canonical answer match the bank snapshot.
- [ ] Mascot and style images are correct, readable single-frame references.
- [ ] Exactly three prompts are present in order, first generate and then two extend prompts.
- [ ] Requested question/answer text, local cue timing and boundary handoff are visible in the prompt.
- [ ] Target is portrait 9:16 with approximately 24-30 seconds intended total.

## User Runs In Flow

- [ ] User creates the first segment with the supplied references and first prompt.
- [ ] User extends the accepted result with the second prompt, then extends with the third.
- [ ] Record actual segment/total durations; do not assume extend increments equal requested durations.
- [ ] Check character/style consistency, continuous action/camera/environment and absence of an unintended restart.
- [ ] Check exact question and answer spelling, legibility, sufficient visibility and reveal ordering in the actual video.
- [ ] Confirm explanation does not change the source fact and that stylized action is not misleading factual evidence.
- [ ] Check ending is coherent and any CTA is appropriate to the channel/audience.
- [ ] Record rejected attempts and prompt edits that were needed. Update the package revision if edits are to be retained; do not claim the original prompt produced an edited result.

## Acceptance Record

For each sample, record pass/fail/pending, user observations, requested versus actual timing, issue IDs, accepted package revision and evidence reference. A model-produced beautiful scene with wrong answer text fails. A correct package without a reviewed video leaves footage acceptance pending, not failed software by default.

If the active Flow model cannot follow the target duration/extend profile, record that mismatch and ask the user for an approved timing change. Never automatically switch providers, add segments, build post-production text or misrepresent the observed duration.

## Final User Decision

Only record accepted when the user explicitly says the complete work is accepted after checking remaining issues. Record their decision date and concise confirmation; do not infer approval from silence. Publication itself is optional and user-owned. The folder remains untouched for the user to delete personally later.
