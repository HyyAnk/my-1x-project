# Execution Roadmap

```text
01 Inventory and baseline
        |
02 Contracts and storage (contract review gate)
        |
03 Mixed topics and one-question allocation
        |
04 Three-segment script and deterministic prompts
        |
05 References, cover, publishing and export
        |
06 Complete Studio and asynchronous integration
        |
07 Controlled portrait retirement (deletion review gate)
        |
08 Regression, real Flow review, user acceptance
```

Sequential execution is the default. Phase numbers are product phases, not the unrelated coordination framework's Phase 0-5 roadmap. Do not run two phase prompts concurrently against main.

| Phase | Required Predecessor | Testable Deliverable                                            | Review Emphasis                                    |
| ----- | -------------------- | --------------------------------------------------------------- | -------------------------------------------------- |
| 01    | none                 | Classified source/data inventory and baseline evidence          | Complete dependencies, safe cleanup scope          |
| 02    | 01 reviewed/released | Validated isolated records, atomic/replay-safe repository       | Contract shape, concurrency, file safety           |
| 03    | 02 reviewed/released | Five mixed topics, correct confirmation, real draft destination | No Episode masquerading, bank fidelity             |
| 04    | 03 reviewed/released | Three validated prompts from source and references              | Continuity, text, cancellation/invalidation        |
| 05    | 04 reviewed/released | Complete export bundle and component retries                    | Reference identity, portrait cover, archive safety |
| 06    | 05 reviewed/released | Usable Studio with live synchronization                         | Slow/failure/concurrent UX, desktop/mobile         |
| 07    | 06 reviewed/released | Legacy portrait removed, landscape retained                     | Exact deletion targets, no protected-data loss     |
| 08    | 07 reviewed/released | Regression evidence and manual acceptance report                | No skipped failures or fabricated approval         |

## Cross-Phase Rules

Contracts must be reviewed before Phase 03. Removal manifest must be refreshed and reviewed immediately before Phase 07 deletion, even if it passed Phase 01. A later code drift can invalidate older inventory.

The next phase prompt reviews the predecessor before modifying product code. If the predecessor is incomplete or review finds blocking defects, stop and issue a repair list; do not silently take ownership of another phase's implementation. Re-run the predecessor prompt or use the resume prompt to repair under proper claims.

Initial phase outputs may be server-level harnesses, but must be executed and tested. Phase 03 must include a minimal real draft destination for its visible Short-Reel selection. Phase 06 extends that destination rather than inventing another navigation path.

No phase may add an unmapped production directory and defer zone registration to final integration. Phase 01 prepares the zone proposal; the protocol integrator approves/applies it before the first affected product file is created. Existing mapped modules may be implemented while that approval is pending, without falsely marking a dependent phase complete.

## Definition Of Phase Completion

Implementation evidence is complete, required checks pass on the current code, no blocking review findings remain, handoff is written, and registry verification/release is confirmed. A check run before the last edit is not current evidence. User acceptance of the entire product is a separate final gate.

## Execution Size

Break each phase into the listed test-first slices. Do not trade quality gates for a smaller model. If a model repeatedly fails the same contract/concurrency task, preserve its partial work and escalate to the user/reviewer with the exact failed assertion. Do not keep generating speculative rewrites.
